# 智读小站 · 部署到阿里云（2 核 2G 版）

> 这份文档对应「模型全部走国内 API」的版本：服务器只负责跑网页、切分文档、调用接口，
> **不做任何 AI 计算**。所以不需要显卡，也不用下载任何模型，2 核 2G 够用。
>
> 如果你要部署的是「本地模型 + 显卡」的 Windows 版本，请看 `docs/安装文档.md`。

---

## 0. 先看懂这套方案怎么跑（6 行）

| 环节 | 用的什么 | 在哪跑 |
|---|---|---|
| 上传文档、切块 | PyMuPDF / python-docx | 你的服务器（CPU） |
| 建索引（向量化） | 阿里云百炼 `text-embedding-v3`，1024 维 | 阿里云（接口） |
| 检索排序（精排） | 阿里云百炼 `gte-rerank-v2` | 阿里云（接口） |
| 生成摘要 / 回答 | DeepSeek `deepseek-chat` | 深度求索（接口） |
| 存文件、存账号 | 本地磁盘 `backend/data`、`backend/uploads` | 你的服务器 |
| 网页 | `index.html` + Flask | 你的服务器（CPU） |

**为什么能砍到 2 核 2G**：原来要在这台机器上跑一个 0.6B 的向量模型（至少吃 1.2G 内存 + 慢），
现在换成接口，内存占用从 2G+ 降到 200MB 左右。

---

## 1. 买服务器 & 开端口

- 规格：**2 核 2G**，系统镜像选 **Ubuntu 22.04 64 位**（不要选 CentOS，命令不一样）
- 磁盘：40G 够用（一篇论文约 3~10MB）
- 带宽：1~3 Mbps 够 3~5 个人同时用；人多往上加
- 地域：选离使用者最近的（如华东1·杭州）
- 安全组（防火墙）**只开两个端口**：
  - `22`（SSH 登录）
  - `8080`（网页访问）

> ⚠️ 不要开 80 / 443。用 80/443 + 域名必须做 ICP 备案，没备案会被拦。
> 用 `http://公网IP:8080` 可以直接访问，不需要备案。

## 2. 把代码传到服务器

### 方式 A：服务器上直接 clone（推荐，服务器能连 GitHub 时）

```bash
sudo apt update
sudo apt install -y git
cd /opt
sudo git clone https://github.com/changliu736-design/zhidu-xiaozhan.git
sudo chown -R $USER:$USER /opt/zhidu-xiaozhan
```

国内服务器拉 GitHub 有时很慢，卡住就按 Ctrl+C，改用方式 B。

### 方式 B：本机打包再上传（最稳）

在本机项目文件夹执行（Windows 用 PowerShell）：

```powershell
# 在仓库根目录执行，生成一个不含 .git 的压缩包
tar -czf zhidu.tar.gz --exclude=.git --exclude=backend/.env --exclude=__pycache__ .
```

然后上传：

```powershell
scp zhidu.tar.gz root@你的公网IP:/opt/
```

服务器上解压：

```bash
cd /opt
mkdir -p zhidu-xiaozhan && tar -xzf zhidu.tar.gz -C zhidu-xiaozhan
```

> `backend/.env` 里是密钥，**不要**打进压缩包，服务器上单独创建（第 4 步）。

## 3. 装 Python 环境和依赖

```bash
sudo apt update
sudo apt install -y python3 python3-venv python3-pip

cd /opt/zhidu-xiaozhan
python3 -m venv .venv
source .venv/bin/activate

# 用阿里云 pip 镜像（快很多）
pip config set global.index-url https://mirrors.aliyun.com/pypi/simple/

pip install -r backend/requirements.txt
pip install gunicorn
```

说明：

- `requirements.txt` 里**没有 torch**，整个依赖约 200MB，几分钟装完。
- `requirements-local.txt` 才含 torch / sentence-transformers，**服务器不要装**。
- 装完检查一下关键包：

```bash
python -c "import flask, faiss, fitz, docx, openai; print('依赖 OK')"
```

## 4. 填配置（只有这一步要动手改）

```bash
cd /opt/zhidu-xiaozhan/backend
cp .env.example .env
nano .env
```

必须改的只有 **3 个值**：

```ini
# ① 生成模型：DeepSeek 的 key（sk- 开头）
OPENAI_API_KEY=sk-你的DeepSeek密钥
OPENAI_BASE_URL=https://api.deepseek.com/v1
OPENAI_MODEL=deepseek-chat

# ② 向量模型：阿里云百炼的 key（sk- 开头）
EMBEDDING_PROVIDER=api
EMBEDDING_API_KEY=sk-你的百炼密钥
EMBEDDING_API_BASE_URL=https://dashscope.aliyuncs.com/compatible-mode/v1
EMBEDDING_API_MODEL=text-embedding-v3
EMBEDDING_API_DIMENSIONS=1024

# ③ 精排：复用上面百炼的 key，不用另填
RERANKER_PROVIDER=api
RERANKER_API_MODEL=gte-rerank-v2
```

建议再改这 3 个（省资源，避免被大文件拖垮）：

```ini
OCR_ENABLED=0            # 扫描版 PDF 不做 OCR（省内存；需要时再改回 1 并装 rapidocr）
MAX_CONTENT_LENGTH_MB=20 # 单个文件最大 20MB
```

另外把两个安全盐换成随机值（防伪造登录态）：

```bash
python -c "import secrets; print('SESSION_SALT=' + secrets.token_urlsafe(32)); print('ADMIN_VIEW_SALT=' + secrets.token_urlsafe(32))"
```

把输出的两行贴进 `.env`。

> 保存方法：nano 里 `Ctrl+O` 回车，`Ctrl+X` 退出。

## 5. 自检（不通就别往下走）

```bash
cd /opt/zhidu-xiaozhan/backend
source /opt/zhidu-xiaozhan/.venv/bin/activate
python check_api.py
```

期望输出三项全 `[通过]`：

```
[1/3] 生成模型   [通过] 耗时 2.x s，回复：收到
[2/3] 向量模型   [通过] 耗时 x s，维度 1024，向量已归一化
[3/3] 精排模型   [通过] 耗时 x s，最相关片段排在第 1 位
```

常见报错对照：

| 报错 | 原因 |
|---|---|
| `没有配置 OPENAI_API_KEY` | `.env` 里生成模型的 key 没填 |
| `接口返回 401` | key 打错、或 key 与 base_url 不匹配（百炼的 key 不能配到 DeepSeek 地址） |
| `额.channel.NotFound` | 向量模型的 `EMBEDDING_API_BASE_URL` 少了 `/compatible-mode/v1` |
| 连接超时 | 服务器出网不通，或没配 `EMBEDDING_API_BASE_URL` |

## 6. 启动（用 systemd 守护，关机自动拉起）

创建服务文件：

```bash
sudo nano /etc/systemd/system/zhidu.service
```

粘贴：

```ini
[Unit]
Description=Zhidu Xiaozhan (RAG reader)
After=network.target

[Service]
Type=simple
User=root
WorkingDirectory=/opt/zhidu-xiaozhan/backend
Environment="PYTHONUNBUFFERED=1"
Environment="TZ=Asia/Shanghai"
ExecStart=/opt/zhidu-xiaozhan/.venv/bin/gunicorn \
    --workers 1 --worker-class gthread --threads 8 \
    --timeout 300 --bind 0.0.0.0:8080 app:app
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

启动并设为开机自启：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now zhidu
sudo systemctl status zhidu --no-pager
```

> **为什么 `--workers 1`**：上传后的索引是在进程内的后台线程里跑的，进度也记在内存里。
> 开多个 worker 会出现「A 进程在索引、你刷新页面被分到 B 进程、看不到进度」的串台问题。
> 用 1 个进程 + 8 个线程，既不会串台，也足够几个人同时用。

看日志：

```bash
sudo journalctl -u zhidu -f
```

## 7. 验收

```bash
# 健康检查：期望 embedding.mode=api、llm.available=true、reranker.mode=api
curl -s http://127.0.0.1:8080/api/health
```

浏览器打开 `http://你的公网IP:8080`：

1. 注册一个账号并登录
2. 上传一篇 PDF（等状态变成「索引就绪」，一篇 30 页约 10~30 秒）
3. 提问，看回答里有没有 `p.1`、`p.3` 这样的出处按钮，点一下能不能跳到原文
4. 生成一次摘要
5. 试一次学术翻译

全过 → 部署完成。

### 建管理员账号

管理后台（`http://你的公网IP:8080/admin.html`）需要管理员身份。第一个账号不会自动变管理员，要手动提：

```bash
cd /opt/zhidu-xiaozhan/backend
source /opt/zhidu-xiaozhan/.venv/bin/activate
python manage.py create-admin --username 你的用户名
python manage.py list-users
```

## 8. 日常运维

```bash
# 重启 / 停止 / 看状态
sudo systemctl restart zhidu
sudo systemctl stop zhidu
sudo systemctl status zhidu --no-pager

# 备份（账号、文档、索引、上传的原文件都在这里）
cd /opt/zhidu-xiaozhan
tar -czf ~/zhidu-backup-$(date +%F).tar.gz backend/data backend/uploads

# 更新代码（用方式 A 部署时）
cd /opt/zhidu-xiaozhan && git pull && sudo systemctl restart zhidu
```

> 索引文件与「向量模型名」绑定。以后如果换了向量模型（比如从 `text-embedding-v3`
> 换成别的），老文档会显示「需重建索引」，点一下重建即可，不用重新上传。

## 9. 花钱大概多少

| 项目 | 估算 |
|---|---|
| ECS 2 核 2G | 包年约 ¥1000~1600/年（按量约 ¥0.15/小时） |
| 百炼 `text-embedding-v3` | 约 ¥0.5/百万 token；一篇 30 页论文约 3 万 token ≈ 1.5 分钱；1000 篇 ≈ 15 元 |
| 百炼 `gte-rerank-v2` | 有免费额度，日常提问量约几元/月 |
| DeepSeek `deepseek-chat` | 约 ¥1/百万输入 token、¥2/百万输出 token；一次问答约 1 分钱 |

结论：**日常几十个学生用，每月 API 成本通常不到 50 元**。建议在百炼和 DeepSeek 后台都设个消费限额。

## 10. 坑（务必看一遍）

1. **别开 80/443**：没有 ICP 备案会被拦。先用 `IP:8080`，要正式域名再走备案。
2. **一次只传一篇大文件**：2G 内存解析 200 页的 PDF 会紧张。`MAX_CONTENT_LENGTH_MB=20` 是保险丝。
3. **`.env` 绝对不能提交到 Git**：仓库的 `.gitignore` 已经排除 `backend/.env`，别用 `git add -f`。
4. **安全组只开 22 和 8080**：数据库、其他端口一律不要暴露。
5. **时区**：服务文件里已设 `TZ=Asia/Shanghai`，否则审计日志时间会差 8 小时。
6. **欠费停机**：ECS 欠费会直接关机；API 欠费会导致上传时索引失败、提问报错。都设个余额提醒。
7. **换服务器要迁两样东西**：`backend/data`（账号+索引）和 `backend/uploads`（原文件），一起打包带走。
8. **别在 2 核 2G 上装本地模型**：`requirements-local.txt` 是给有显卡的电脑用的，装到服务器上会直接 OOM。

## 11. 卡了怎么办

| 现象 | 先查这里 |
|---|---|
| 网页打不开 | 安全组有没有放行 8080；`sudo systemctl status zhidu` 是否 running |
| 登录后马上掉线 | `.env` 里 `SESSION_SALT` 是不是空、服务有没有重启过 |
| 上传后一直「索引中」 | `sudo journalctl -u zhidu -f` 看是否有接口报错（多半是 key 或余额） |
| 提问报「向量服务不可用」 | 跑 `python check_api.py`，看向量那项 |
| 回答里没有出处 | 精排被降级了，看日志里有没有 rerank 失败；跑 `check_api.py` 第三项 |
